# Target Account Scoring Model (Finance POC)

## Purpose
Prioritize first design-partner outreach with a consistent, evidence-driven scoring method.

## Score dimensions (100 total)

1. **Workflow pain (0–25)**
- 0: little/no close friction
- 10: moderate manual reconciliation
- 25: severe close bottlenecks and rework

2. **API readiness (0–25)**
- 0: no usable APIs
- 10: partial APIs or heavy constraints
- 25: strong API coverage + workable auth model

3. **Governance urgency (0–20)**
- 0: low compliance pressure
- 10: moderate controls required
- 20: high audit/approval requirements

4. **Pilot velocity (0–15)**
- 0: long internal procurement/setup
- 8: moderate setup complexity
- 15: can start pilot quickly with clear owner

5. **Expansion potential (0–15)**
- 0: narrow use case, low future scope
- 8: moderate adjacent workflow potential
- 15: strong multi-team or multi-workflow expansion path

## Priority bands
- **Tier A (75–100):** pursue immediately
- **Tier B (55–74):** pursue after Tier A
- **Tier C (<55):** park or revisit later

## Tie-breakers
When scores are close, prioritize:
1. Faster start date
2. Stronger internal champion
3. Better data/API access today

## Qualification hard stops
Disqualify for current POC if any true:
- No owner for pilot decisions
- No workable API access for in-scope workflow
- No tolerance for pilot-level iteration
